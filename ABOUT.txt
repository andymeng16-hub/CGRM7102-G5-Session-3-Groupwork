  1.  HOW TO OPEN IT
--------------------------------------------------------------------------------

  The guide is not a single file. The page reads its layout from
  styles.css, its behaviour from app.js, its survey from data/, and its
  photographs and map tiles from assets/. Opened on its own, the page puts
  up a notice instead of the guide, because the folders beside it are
  missing.

  The page is named so that it can be found in a folder full of files:

    CLICK ME (If not work, read about.txt).html

  A small index.html sits beside it and forwards to the same page, so a
  bare folder address also works.

  Two ways in:

    a)  Download the whole repository (Code, then Download ZIP), unzip it,
        and open CLICK ME (If not work, read about.txt).html in a browser.
        Everything works offline once it is unzipped, including the map,
        which uses committed tiles.

        On Windows, run open-on-windows.bat in the unzipped folder instead
        of opening the page directly. Section 2 says why.

    b)  Publish the folder with GitHub Pages and open the site it gives you.
        This is the way that asks nothing of the reader's machine.

  GitHub shows the source of an HTML file rather than the page it draws, so
  the link to this text file is the dependable way in:

    This file, rendered
      https://github.com/andymeng16-hub/CGRM7102-G5-Session-3-Groupwork/blob/main/ABOUT.txt

    This file, plain text
      https://raw.githubusercontent.com/andymeng16-hub/CGRM7102-G5-Session-3-Groupwork/main/ABOUT.txt

    Whole repository as a zip
      https://github.com/andymeng16-hub/CGRM7102-G5-Session-3-Groupwork/archive/refs/heads/main.zip

  These links assume the main branch and a public repository.

  2.  PLATFORMS, AND THE MACHINE THIS WAS BUILT ON
--------------------------------------------------------------------------------

  Built and tested on macOS, in Safari and in Chrome. The guide is plain
  HTML, CSS and JavaScript with no build step and no dependencies, so none
  of it is particular to macOS: every file it reads sits in this folder.

  Windows reads the same files, but Windows adds one thing of its own. A
  folder that came out of a downloaded ZIP carries a mark saying it came
  from another computer, and some browser and security settings read that
  mark as a reason to hold back the pictures and the scripts of a page
  opened from the local disk. The guide then opens as a page of empty
  boxes: the words are there, the photographs are not. The files are
  intact, and it happens only on the machines where that setting is on,
  which is why it can look like a fault in the guide.

  Three ways round it, best first:

    a)  Double-click open-on-windows.bat in this folder. It clears the mark
        on every file, serves the folder on http://127.0.0.1:8765 and opens
        the guide there. Python or Node has to be on the computer already;
        both are common and either will do. Nothing is installed and
        nothing leaves the machine.

    b)  Right-click the ZIP before unzipping it, choose Properties, tick
        Unblock, then extract. Every file comes out unmarked.

    c)  Serve the folder yourself and read it at http://localhost:8000
        with python -m http.server 8000. A page served over HTTP is not a
        local file, so the mark does not apply to it.

  Two things that break the pictures on any system, worth ruling out first:

    Extract the whole archive. Unzipping only the HTML file, or dragging
    that one file out of the archive window, leaves the folders beside it
    behind.

    Keep the folder structure. assets/photos, assets/tiles and data must
    stay next to the HTML file, under the same names.

  A folder path containing a hash mark or a percent sign also breaks the
  page, because a browser reads those characters as instructions rather
  than as part of the path.

  If a photograph still does not appear, the browser console (F12, then
  Console) names every file the guide could not read, so a missing file can
  be identified rather than guessed at.

  这一版在 macOS 上编写与测试，用的是 Safari 与 Chrome。网页本身是纯
  HTML、CSS 与 JavaScript，无需编译，没有外部依赖，所有文件都在本文件夹
  内，与制作它的系统无关。

  Windows 上唯一多出来的一道坎，是系统会给下载来的压缩包里的文件加一个
  「来自其他计算机」的标记，部分浏览器与安全设置据此不放行本地页面里的
  图片与脚本，页面于是只剩文字、不见照片。文件本身没有损坏，只在开启了
  那项设置的机器上出现，所以看上去像是网页坏了。

  三种办法，按顺序试：双击 open-on-windows.bat，本机需已装 Python 或
  Node，它会清除文件标记、把本文件夹挂到本机地址上打开；或在解压前右键
  压缩包，选「属性」，勾选「解除锁定」，再解压；或在文件夹内执行
  python -m http.server 8000，再用 http://localhost:8000 打开，走本机
  地址的页面不算本地文件，标记对它无效。

  另外两点与系统无关，但同样会让图片消失：请整个压缩包一起解压，只解出那个
  网页文件会把旁边的文件夹留在压缩包里；assets 与 data 必须与网页文件同级，
  名字不要改。文件夹路径里也不要有井号或百分号，浏览器会把这两个符号当成
  指令而不是路径的一部分。

--------------------------------------------------------------------------------
  7.  A NOTE ON THE NUMBERS
--------------------------------------------------------------------------------

  The route is 2.19 km across the island, from Kiu Tsui Pier to Hap Mun Bay,
  walked in 2 h 28 min on site. Elevation is CGIAR SRTM 30 m, which reads
  77 m at the highest point of the corridor where the AFCD records 136 m for
  the island, so the relief here is shallow and is labelled as indicative
  wherever it is drawn.

  Shade is tested, not guessed. The sun is placed with the NOAA position
  algorithm for 13 November 2026, and each position along the path is tested
  at the minute the group reached it: a ridge in the way takes the share of
  sunlight to nothing at once, canopy takes it down gradually. The three
  classes used throughout are unshaded above 0.9, partly shaded from 0.4 to
  0.9, and mostly shaded below 0.4.
